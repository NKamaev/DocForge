## [23:10] BUG-054 закрыт — единый счётчик версий шаблона

- **Причина:** `publish()` нумеровал как `max+1`, а `saveVersion()`/`rollback()`
  — как `major*10000+minor`; обе писали в `template_version.version_number`
  (UNIQUE). Воспроизведено: save 1.1 → publish 1.2 → save снова 1.2 → **500**;
  `registry.version` расходился с `major/minor`.
- **Фикс (`c0f4730`):** один аллокатор `allocateVersion()` для всех трёх
  писателей (MAJOR → major+1/minor=0, прочие → minor+1, overflow → следующий
  major); `max(pgMax, mongoMax)` — только floor монотонности для осиротевших
  снимков. Registry/TemplateVersion/снимок получают один тройной номер.
  `toVersionDTO` для легаси (`<10000`) → `vN.0`.
- **Миграция `V017`**: выравнивает компоненты существующих строк, только labels
  (`version_number` не меняется → пины документов живут).
- **Тесты:** `TemplateVersionNumberingIT` 8 + unit overflow; `template.*` 37/3
  (красные — пре-существующие, `@WithMockUser("testuser")` без строки → BUG-061).
- **Ревью REQUEST CHANGES → исправлено** W1 (saveVersion/rollback через
  аллокатор — симптом оставался открытым на существующих данных), W2 (миграция
  V017), W3 (fallback-лейбл). W4 → **BUG-062** (черновик `version=1` при
  `major/minor=1.0` — две шкалы в одной колонке).
- **Урок:** один счётчик = один аллокатор; «починить publish» недостаточно, если
  в колонку пишут ещё два метода. Не-транзакционная запись (Mongo-снимок) —
  источник «осиротевших» номеров, нужен floor монотонности.
- **Обновлены теги:** `tickets/BUG-054`, `tag-index.md`.
