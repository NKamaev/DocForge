# 2026-10-24

## [01:10] BUG-058 закрыт — версионная авторизация при создании документа

- **Причина:** `POST /api/documents` принимал `templateVersionNumber` без
  проверки публичности версии; без явной версии документ закреплялся за
  последним сохранённым черновиком, а не за опубликованной версией.
- **Воспроизведено:** владелец сохраняет черновик (`MINOR`) с телом
  `DRAFT_SECRET_BODY`, публикует шаблон; не-владелец создаёт документ с
  `templateVersionNumber` черновика → 201 и `generate` отдаёт секретный текст.
- **Фикс (`8a1516b`):**
  - `DocumentServiceImpl.create`: явная версия → 404 (нет версии) / 403
    (черновик у гостя) / 404 (нет Mongo-снимка); без версии → гость получает
    последнюю опубликованную, при отсутствии опубликованных → 403, live-шаблон
    только для легаси-шаблонов без строк версий;
  - «опубликована» = `PUBLISH` / легаси `NULL` / `ROLLBACK` с опубликованным
    источником (рекурсия по `rollback_from`); `MAJOR`/`MINOR` — только владельцу;
  - снимки резолвятся по `id` версии (фолбэк по номеру) — пинится тот же
    снимок, который отдаёт `GET /versions/{n}`;
  - `V018` помечает легаси `bump_type IS NULL` как `PUBLISH`;
  - фронт: в списке только инстанцируемые версии, текст ошибки из
    `ProblemDetail.detail`, подсказка соответствует 403.
- **Тесты:** `DocumentCreateVersionPermissionIT` 18, `CreateDocumentModal.test.ts`
  21; `document.* + template.*` 286/5 (известные пре-существующие).
- **Ревью:** 3 итерации; закрыты 2 BLOCKER (NPE на null ownerId; «безснимковый»
  документ для гостя) и 4 WARNING. Follow-up: **BUG-068** (изменяющие операции
  шаблона без проверки владельца — через `rollback` атакующий подменяет живой
  опубликованный шаблон черновиком), **BUG-069** (`ShareDialog` читает
  `message` вместо `detail`).
- **Урок:** «опубликовано» — это свойство происхождения версии, а не только её
  `bump_type`: откат наследует публичность источника. И любой запрет контента
  бессмыслен, если рядом есть endpoint, меняющий сам шаблон (см. BUG-068).

## [03:40] BUG-059 закрыт — чтение чужих черновиков шаблона

- **Причина:** read-endpoints модуля шаблона не проверяли владение: чужой
  черновик читался через `GET /templates/{id}` (живое тело), `/versions`
  (черновики в списке), `/versions/{n}` (снимок) и `POST /templates/{id}/export/docx|pdf`
  (контроллер читал `TemplateRepository` напрямую — минуя сервис и слои).
- **Фикс (`9f5d54a`):**
  - правила чтения перенесены в сервис (`getReadable`, `listVisible`,
    `listVersionsVisible`, `getSnapshotVisible`, `getDiffVisible`); опубликованный
    шаблон — всем, черновик — владельцу и админу; чужие черновики отфильтрованы
    в SQL (пагинация корректна);
  - «опубликованность» версии — единый источник истины с BUG-058;
  - исключение для коллаборации: черновую версию читает участник документа,
    привязанного к ней (`DocumentService.hasAccessibleDocumentForTemplateVersion`
    + `DocumentPermission.READ`) — иначе сломался бы `/fill` у соавтора;
  - `ExportController` переведён на `templateService.getReadable` (нарушение
    слоёв устранено);
  - откат опубликованного шаблона к черновику запрещён (409) — иначе живой
    опубликованный шаблон отдавал бы всем черновое содержимое;
  - фронт: экран «Нет доступа к шаблону», read-only режим для не-владельцев,
    `authStore.isUserResolved` вместо лишнего `/users/me`, общий
    `api/errorMessages.ts`.
- **Тесты:** `TemplateReadPermissionIT` 14, `TemplateExportPermissionIT` 4,
  `TemplateVersionAccessIT` 8; фронт 21 файл / 187 тестов; backend
  template+document+export 332/5 (известные пре-существующие).
- **Ревью:** 2 итерации; BLOCKER (обход через экспорт) и 5 WARNING закрыты.
  Follow-up: **BUG-068** (write-scope шаблона: publish/unpublish/versions/
  rollback/PUT + оракулы `validate`/`scripts/test`), **BUG-070** (дубль),
  **BUG-069** (`ShareDialog` читает `message` вместо `detail`).
- **Урок:** правило доступа нужно проверять на **всех** путях чтения одних и
  тех же данных — экспорт шаблона обошёл защиту, а правило «опубликованности»
  должно быть единственным, иначе чтение и инстанцирование разойдутся.

## [05:20] BUG-061 закрыт — `catch` отравлял транзакцию (весь backend зелёный)

- **Причина:** `currentUserId()` звал бросающий `UserService.getCurrentUser(login)`
  внутри `@Transactional` и глушил `ResourceNotFoundException`. Вложенный
  `@Transactional` (REQUIRED) присоединяется к транзакции вызывающего, поэтому
  исключение помечало **общую** транзакцию rollback-only: метод выглядел
  успешным, а на коммите вылетал `UnexpectedRollbackException`.
- **Воспроизведено:** `@WithMockUser("testuser")` — пользователя нет в `users`:
  `TemplateServiceImplIT.publish()/update()`, `TemplateControllerIT`, 
  `DocumentServiceImplIT.create()`.
- **Фикс (`83aa862`):** не бросающие лоупы `UserService.findUser(login)` /
  `findUserById(id)` (Optional, null-safe); `TemplateServiceImpl`,
  `DocumentServiceImpl`, `AuditServiceImpl` используют их; из `document` и
  `audit` убраны кросс-модульные импорты `user.UserRepository`; атрибуция для
  существующего пользователя не изменилась.
- **Тесты:** `UserServiceImplTest` 6, `TemplateServiceUnknownUserIT` 3,
  `DocumentServiceUnknownUserIT` 2 (в т.ч. ревизия с удалённым автором —
  прежний путь `toRevisionDTO`); все RED на старом коде; guard «пользователя
  нет» на чистом SQL (тесты компилируются и на старом дереве).
- **Ревью APPROVE**; замечания по качеству тестов закрыты.
- **Побочный эффект:** весь backend — **345 тестов, 0 падений** (было 5);
  последнее устаревшее утверждение MANAGER/SHARE исправлено отдельным
  коммитом `317c038`.
- **Follow-up:** BUG-071 (аудит: `catch` внутри транзакции + `details` не JSON в
  JSONB → записи теряются), TASK-067 (нарушения границ модулей в
  permission-сервисах), TASK-068 (ещё два `catch (Exception)` в транзакциях).
- **Урок:** best-effort-атрибуция не должна бросать исключения из
  транзакционного кода — нужен отдельный не бросающий API; unit-тесты на моках
  такую ошибку не видят, нужен IT с несуществующим пользователем.
- Новый тег `pitfalls:transactions`; исправлена устаревшая запись о BUG-019 в
  `pitfalls:conditional-rendering` (фильтр условий — в `ConditionalNodeFilter`,
  а не в экспортёрах).

## [07:30] BUG-068 закрыт — write-scope шаблона (владелец/админ)

- **Причина:** в модуле шаблона не было проверки владения на изменяющих
  операциях: любой пользователь мог `PUT`/`DELETE`/`publish`/`unpublish`/
  `versions`/`rollback`, а `rollback` на черновик подменял живое тело
  опубликованного шаблона черновым контентом. Два read-оракула (`validate`,
  `scripts/test`) отдавали метаданные черновика и текст исключения скрипта.
- **Фикс (`2d5487c`):**
  - `TemplateServiceImpl.assertCanModify` — владелец (`owner_id`) или админ
    (`ROLE_ADMIN`/`users.is_admin`), иначе 403 «Нет прав на изменение шаблона»;
    fail closed (неизвестный логин, отсутствие аутентификации → отказ);
    `ROLE_ADMIN` проверяется до поиска пользователя;
  - защищено 8 операций, включая оракулы;
  - `TemplateListItemResponse.ownerId` → фронт прячет publish/delete для чужих
    шаблонов; удалён мёртвый дубль `TemplateList.tsx`;
  - **V019** — backfill `owner_id` из `template_version.created_by`/`audit_log`
    (в dev-базе восстановлена 1 строка из 830: легаси-данные без авторства
    остаются admin-only — это осознанный fail-closed).
- **Тесты:** `TemplateWritePermissionIT` 10 (+ инварианты «ничего не
  изменилось»), починены **73** сломавшихся теста (`@WithMockUser` без
  пользователя в `users`), `TestAuth`/`AuditTestSupport`; **backend 356/0**,
  фронт 22 файла / 198 тестов.
- **Ревью APPROVE.** Закрыто: порядок проверки `ROLE_ADMIN`, инварианты в
  HTTP-пути теста, инвариант BUG-061 на незащищённом пути, детерминированное
  ожидание асинхронного аудита. Документация: `template/README.md` (включая
  заметку об асимметрии read/write-гардов), `docs/architecture.md` §10.2,
  `docs/specs/contracts/api-contracts.md`.
- **Follow-up:** **BUG-072** (JwtAuthFilter: неизвестный логин → 500 вместо
  401/403), **BUG-070** закрыт как дубль (CANCELLED).
- **Урок:** защита контента бессмысленна, если рядом есть endpoint, меняющий
  сам объект (BUG-059 закрыл чтение, BUG-068 — запись); правило доступа стоит
  в сервисе (resolve из SecurityContext), иначе контроллеры обходят его.
