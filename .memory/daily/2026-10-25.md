# 2026-10-25

## [00:40] BUG-071 закрыт — аудит терял записи

- **Причина (две):** (1) `catch (Exception)` внутри `@Transactional(REQUIRES_NEW)`
  в `AuditServiceImpl.log` — упавшая вставка помечала транзакцию rollback-only,
  `catch` глотал ошибку, но `commit` бросал `UnexpectedRollbackException`;
  (2) `audit_log.details` — `jsonb`, а вызывающие передают произвольный текст
  (`"version=1.0,bumpType=MINOR"`, `"fromVersion=…,newVersion=…"`) →
  `invalid input syntax for type json` → запись молча терялась.
- **Фикс (`d022936`):** транзакция вынесена в отдельный бин `AuditLogWriter`
  (REQUIRES_NEW), `try/catch` теперь **вне** транзакционной границы;
  `normalizeDetails` приводит details к валидному JSON (валидный — как есть,
  `"null"` → SQL NULL, прочее → `{"note": "<текст>"}`), вырезает NUL и непарные
  суррогаты, jsonb-небезопасные escape принудительно заворачивает.
- **Тесты:** `AuditServiceImplTest` 14 (edge cases: пустая строка, пробелы,
  трейлинг-мусор, `"null"`, JSON-скаляры, NUL-escape/литеральный NUL),
  `AuditNonJsonDetailsIT` 2 (реальные saveVersion/rollback оставляют строку с
  валидным JSON); `AuditTestSupport.awaitAuditDetails`. **Backend 372/0.**
- **Ревью:** 2 итерации; BLOCKER (пустая строка и `{"a":1}garbage` проходили
  `readTree` без исключения и уходили в jsonb как есть) и WARNING (U+0000 /
  непарные суррогаты) закрыты.
- **Follow-up:** **BUG-073** (`FeedbackController` собирает JSON вручную —
  многострочные описания баг-репортов дают невалидный JSON), **TASK-068**
  (остальные `catch` внутри транзакций).
- **Урок:** «свободный» текст в JSON-колонку нужно нормализовать на границе
  записи, а `try/catch` держать вне транзакционного метода — иначе запись
  теряется молча, а ошибка в логе врёт о причине.
