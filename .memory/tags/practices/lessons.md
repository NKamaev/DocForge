## [2026-10-22] UUID в MongoDB: legacy-порядок байт

- **MongoDB хранит UUID в legacy-порядке Java-драйвера** (слова по 4 байта в обратном порядке, halves переставлены). Поэтому `mongosh` с `Binary.createFromBase64(<big-endian bytes>)` **не находит** документы, которые видит приложение. Пример: UUID `710749c1-de06-492a-a4fb-a96b73cafd13` хранится как base64 `KkkG3sFJB3ET/cpza6n7pA==`. Для проверок в mongosh либо декодируй через `toString("base64")` из самих документов, либо используй профайлер.
- **Диагностика через профайлер Mongo** (`db.setProfilingLevel(2)`, затем `db.system.profile`) показывает фактический `filter` и `nreturned` — быстрее, чем гадать по стеку Spring.
- **`IncorrectResultSizeDataAccessException` = дубли, а не неверный UUID.** Если finder возвращает `Optional`, а данных ≥2 — Spring бросает исключение. Лечится ordered-finder'ом (`findFirstBy...OrderBy...Desc`), а не удалением данных.
- **Две записи в разные хранилища = orphan'ы.** Снимок в Mongo и `TemplateVersion` в PG пишутся неатомарно; при откате PG в Mongo остаётся снимок. Любая нумерация «по одной БД» должна учитывать максимум из обеих.

## [2026-10-12] Тестовые шаблоны/документы — только полные

- **Тестовый шаблон должен быть полным:** параметры разных типов + опросный лист (страницы → вопросы, привязанные к `parameter_code`) + текст с расставленными `parameter_field`-нодами и условными блоками. Шаблон без ОЛ даёт документы с пустым опросным листом — по нему нельзя верифицировать ОЛ/document flow. Реальный кейс: шаблон `0bb2c0bd` «Договор поставки 2» (только параметр `test_param`, ОЛ нет) → документ «Тест 1» и QA-документ с пустым `/fill`.
- **Публикация — точка среза.** ОЛ/параметры, добавленные ПОСЛЕ публикации, не попадают в снапшот: документы создаются из снимка публикации (v10002). Опубликованный шаблон блокирует редактирование — сначала «Снять с публикации».
- Процедурно: требование зафиксировано в `skill:template-create` (раздел Mandatory для тестовых шаблонов) и `skill:test-write` (раздел «Test data fixtures»).

## [2026-10-12] Уроки TASK-064 (structural rich-diff)

- **Схема ProseMirror — не мягкая:** контейнеры (`bulletList`/`table`/`tableRow`) ограничивают тип детей. Проверяй вывод в тестах через `getSchema(ext)` + `PMNode.fromJSON(schema, doc).check()` — TipTap молча рендерит невалидное. (Детали — `pitfalls:tiptap-react`.)
- **Stray `.js` из отменённого агента:** отменённый транспайл-воркер эмитнул 148 `.js` рядом с `.ts/.tsx`; Vite резолвит `.js` **раньше** `.tsx` → затенение исходников. Проблема не видна в `git status`, если директория untracked (показывает строку каталога, не файлов) — проверяй `find frontend/src -name '*.js'`.
- **`buildWorkspaceExtensions` (TASK-064)** — единый источник списка расширений workspace; опции `{ collaboration?, diff? }`. Diff-рендер и рабочий редактор используют один билдер.

## [2026-10-12] Процессные уроки (координация TASK-064)

- **Уточняй UX-требования до реализации.** «Изменения прямо в тексте» оказалось неоднозначным (структура vs plain) → вариант A (`842890a`) переделан на вариант B (`84a3674`). Прототип/скриншот дешевле полной реализации.
- **Манипуляция JSON-деревом TipTap требует schema-guard.** TipTap не валидирует контент по умолчанию; `getSchema(ext)` + `PMNode.fromJSON(schema,doc).check()` в тестах — обязательный барьер.
- **Отмена зависшего агента ≠ отсутствие правок.** Сначала `stat -c '%y'`/`git diff`/`find`, потом решение о доделке. Два `@frontend`-зависания восстановлены вручную.
- **Дроби делегирование мельче.** Задача «фикс + 6 миноров» в одном вызове агента → зависание. Разбивать на фокусные вызовы.
- **Отчёт `@review` — вердикт доверяй, детали сверяй.** Line-номера/цитаты в отчёте могут не совпадать с кодом; APPROVE подтверждать самостоятельной проверкой.
- **Гигиена верификации:** добавлять `find frontend/src -name '*.js'` (stray-артефакты) в чеклист сборки (см. `pitfalls:build-hygiene`).

## [2026-10-10 10:00] Сводка по багам (из архива задач и git-истории DocForge)

- **REST vs Yjs — всегда гонка**: инициализация ответов из REST должна дожидаться WS-sync (BUG-020), иначе перезапись актуального состояния.
- **Два места рендера условий** (генерация + экспорт) — расхождение порождало BUG-019; держи единый фильтр.
- **Одно state-хранилище на ответы** — локальный React-state вместо Yjs-канала давал BUG-010; канал `yAnswers` единственный.
- **NodeView ≠ сменяемый компонент** — несколько `return` = remount (BUG-013).
- **`setContent` без `emitUpdate:false` = холостые записи** (TASK-009).
- **Скрытие контента должно убирать и пустой контейнер** — `display:none` на span не всегда достаточно (BUG-014).
- **Async-модалки**: guard на unmount/stale + сброс данных при открытии + не глотать ошибки (TASK-030).
- **Рестарт после отката редакции** — программный Yjs-reset, а не reload страницы (BUG-046).
- **Toast реализован через CustomEvent `app-toast`** (BUG-029) — программамый путь покрыт e2e.
