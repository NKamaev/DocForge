# BUG-050 — Документные эндпоинты без permission-check: export docx/pdf, participants

- **Статус:** закрыт (2026-10-22)
- **Создан:** 2026-10-13
- **Источник:** находка `@backend` при исправлении BUG-048

## Суть

Без `DocumentPermission` были доступны:
`GET /{id}/export/docx`, `GET /{id}/export/pdf` (нужен READ),
`GET /{id}/participants` (READ),
`POST /{id}/participants` (MANAGE),
`DELETE /{id}/participants/{userId}` (MANAGE).
Любой аутентифицированный пользователь мог скачать чужой документ и
добавлять/удалять участников.

## Решение (коммит `805820f`)

- Все пять хендлеров получили `@AuthenticationPrincipal UserDetails` +
  `ownerResolver.resolve(...)` и проверку `documentPermissionService.hasPermission`
  до вызова сервисов/экспортёров (по образцу `getById`/`getRevisionDiff`).
- `removeParticipant`: `currentUserId` для вызывающего, path `userId` — цель
  (без shadowing).
- **Тесты:** +10 кейсов в `DocumentControllerPermissionsTest` (deny → 403 и
  `verifyNoInteractions`; allow → проход), 26/26.
- **Ревью: APPROVE.** Смежные находки:
  - **BUG-051** — legacy participants API допускает выдачу OWNER менеджером
    (эскалация; выровнять с `DocumentMembersController`/SHARE).
  - **BUG-052** — `POST /api/documents` без проверки доступа к шаблону и папке.
- Неблокирующие suggestions (не сделано): detail-ассерты в deny-кейсах,
  integration-тест для новых guard'ов, вынос helper'а `requirePermission`.
