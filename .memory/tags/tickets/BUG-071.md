# BUG-071 — Аудит: записи теряются (catch внутри транзакции + details не JSON)

- **Статус:** закрыт (2026-10-25)
- **Коммит:** `d022936`
- **Агенты:** `/backend`, `/test`, `/review`
- **Источник:** ревью BUG-061 (WARNING 3 + follow-up #2)

## Суть

Записи `audit_log` молча терялись. Две причины:

1. **`catch` внутри `@Transactional(REQUIRES_NEW)`** в `AuditServiceImpl.log`:
   упавшая вставка помечала транзакцию rollback-only, `catch` глотал ошибку,
   но `commit` всё равно бросал `UnexpectedRollbackException` — запись
   терялась, а в лог уходила неверная причина.
2. **`details` — колонка `jsonb`, а вызывающие передают произвольный текст**:
   `saveVersion` пишет `"version=1.0,bumpType=MINOR"`, `rollback` —
   `"fromVersion=…,newVersion=…"` → `invalid input syntax for type json` →
   вставка падала (воспроизведено в логах:
   `Failed to write audit log [SAVE_VERSION …]: invalid input syntax for type json`).

## Решение

- новый **`AuditLogWriter`** — `@Transactional(propagation = REQUIRES_NEW)` в
  отдельном бине; `try/catch` в `AuditServiceImpl` теперь **вне**
  транзакционной границы → сбой аудита не влияет на бизнес-транзакцию,
  `UnexpectedRollbackException` невозможен;
- **`normalizeDetails(details)`**:
  - валидный JSON сохраняется как есть; строка `"null"` → SQL `NULL`;
  - пустая строка, мусор после значения (`FAIL_ON_TRAILING_TOKENS`) и прочий
    текст оборачиваются в `{"note": "<текст>"}`;
  - NUL-символы и непарные суррогаты **вырезаются** (jsonb их отвергает);
  - текст с jsonb-небезопасными escape (`\u0000`, суррогатные escape)
    принудительно оборачивается — иначе вставка снова бы падала;
- контракт `AuditService.log` зафиксирован в javadoc.

## Ревью

Две итерации. Первая — **REQUEST CHANGES** (BLOCKER: `""`, `"   "` и
`{"a":1}garbage` проходили `readTree` без исключения и уходили в jsonb как
есть → строка всё равно терялась). Вторая — **APPROVE**; WARNING про
U+0000/непарные суррогаты закрыт санитайзером и принудительным wrap.

## Не входит (заведено отдельно)

- **BUG-073** — `FeedbackController` собирает JSON вручную (`escape()` только
  для `\` и `"`), многострочные описания баг-репортов дают невалидный JSON и
  теперь сохраняются как `{"note": …}`, теряя структуру `elements`/`url`/
  `description` для `bug-report-to-task`.
- **TASK-068** — остальные `catch (Exception)` внутри `@Transactional`
  (`TemplateServiceImpl.buildAutoDescription`, удаление из Mongo в
  `TemplateServiceImpl.delete`/`DocumentServiceImpl.delete`).
- Пул соединений: `REQUIRES_NEW` на асинхронном executor + Hikari (max 10) —
  при всплеске аудита возможен transient starvation (зафиксировано, не критично).
