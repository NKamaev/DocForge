# BUG-051 — Legacy participants API позволяет MANAGER выдать OWNER

- **Статус:** закрыт (2026-10-22)
- **Источник:** ревью BUG-050

## Суть

Legacy-эндпоинты `/api/documents/{id}/participants` принимали
`DocumentRole.valueOf(role)` без ограничений:
- MANAGER мог выдать **OWNER** (эскалация до полного контроля);
- MANAGER мог снять участника с ролью OWNER;
- неизвестная роль (`SUPERUSER`) → `IllegalArgumentException` → **500**.

Воспроизведено: B (MANAGER) → POST role=OWNER = 201; DELETE OWNER = 204;
role=SUPERUSER = 500.

Дополнительно выяснилось: канонический `/members` бросал
`ResponseStatusException(422)`, но catch-all в `GlobalExceptionHandler`
превращал его в **500** — то есть защита существовала только на бумаге.

## Решение (коммит `86b2038`)

- Legacy POST/DELETE требуют `DocumentPermission.SHARE` (как canonical),
  роль парсится (`400` на неизвестную), выдача OWNER не-OWNER'ом → `422`,
  снятие OWNER → `422`.
- `DocumentPermissionServiceImpl.grantRole` **сам** запрещает менять роль
  цели с эффективной ролью OWNER (`ValidationException` → 422). Это закрывает
  обход «понизить выданного OWNER через POST role=EDITOR» и попытку выдать
  роль registry-owner (раньше создавалась невидимая строка участника).
- `grantedBy`/`revokedBy` прокинуты из legacy-контроллера в сервис
  (раньше писались `null`, затирая автора выдачи).
- `GlobalExceptionHandler`: добавлен обработчик `ResponseStatusException`,
  сохраняющий статус. Чинит 422 во всех контроллерах (canonical `/members`,
  `FolderMembersController`) — раньше они были 500.
- Legacy-методы помечены `@Deprecated` (фронтенд использует `/members`).
- **Тесты:** `DocumentParticipantsPermissionIT` — 12 кейсов (OWNER
  grant/remove, demotion через legacy и canonical PUT, registry owner,
  granted_by, EDITOR→403); `DocumentControllerPermissionsTest` 27;
  `DocumentMembersIT` 6; `FolderMembersIT` 7. Suite `document.*` — 188 тестов,
  2 красных (известные пре-существующие: stale assert MANAGER/SHARE и
  `UnexpectedRollbackException`).

## Ревью

REQUEST CHANGES → исправлено:
- **B1** — 4 теста `DocumentControllerPermissionsTest` падали из-за смены
  MANAGE→SHARE (обновлены, добавлен кейс MANAGE-only → 403);
- **B2** — обход через POST-понижение OWNER (закрыт в `grantRole`);
- W5 (audit trail), W6 (registry owner как цель), W7 (фикстуры
  `DocumentMembersIT`), W9 (folder 422) — исправлены; W4 — `@Deprecated`.
Вынесено:
- **TASK-065** — удалить legacy participants API;
- **BUG-060** — OWNER неизменяем: нет снятия/передачи владения;
- **BUG-061** — `currentUserId()` глотает исключение внутри транзакции
  (`UnexpectedRollbackException`).
