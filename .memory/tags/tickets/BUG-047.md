# BUG-047 — Опросный лист пуст (0 вопросов) при наличии вопросов в шаблоне

- **Статус:** закрыт (commit `b0246b4`)
- **Дата:** 2026-10-12
- **Агенты:** `/test`, `/review`; координация — main agent
- **Источник:** feedback form, `audit_log` id=11 (2026-10-10 07:08 UTC), user `71f3dddc`; GitHub Issue #1

## Суть

На `/documents/{id}/fill` левая панель опросного листа показывала «Страница 1 · 0 вопр. / Нет вопросов на этой странице», хотя, со слов пользователя, вопросы в шаблоне заданы. Документ нельзя было заполнить.

## Диагностика (две независимые причины)

**A. Архитектурная несостыковка snapshot vs live.** `DocumentServiceImpl.generate()` читал шаблон из **иммутабельного снапшота** документа (`doc.templateSnapshotId`), а `getQuestionnaire()`, `saveAnswers()` и `create()` — из **live-шаблона** (`templateService.getById`). После редактирования шаблона (например, обнуления `questionnaire`) ОЛ документа пустел, хотя снапшот вопросы сохранял. Ревью подтвердило реальные данные: 1 документ из БД был привязан к снапшоту с вопросами при пустом live-шаблоне (`onlySnap=1`, `onlyLive=0`).

**B. Данные пользователя.** У затронутого шаблона `9ab840e5-…` (Mongo `_id` `f84f7a9de540b89abb9799ad01203ca5`, «Договор поставки») `questionnaire` отсутствовал на **всех** уровнях — и в live, и в снапшотах. Ни у одного из ~60 «боевых» шаблонов в Mongo не было `questionnaire`. Т.е. вопросы никогда/давно не персистились (вероятно, UI до миграции AntD→shadcn `f56583c`, коммит которой — 2026-10-10 09:43, уже после репорта 07:08). Текущий pipeline сохранения/чтения проверен и работает.

Диагноз B означает, что конкретный документ `0964d44b-…` остаётся пустым — данные не восстановимы; фикс закрывает причину A (архитектура). Ремедиация данных — повторно ввести вопросы в шаблон и пересоздать документ.

## Решение (commit `b0246b4`)

`backend/src/main/java/com/docforge/document/DocumentServiceImpl.java`:
- Новый private-хелпер `resolveDocumentTemplate(doc, templateId)`: при `doc.getTemplateSnapshotId() != null` → `snapshotToTemplate(templateService.getSnapshotById(...))`; при `ResourceNotFoundException` (снапшот удалён) → фолбэк на live-шаблон с `log.warn(..., e)`; прочие ошибки пробрасываются (не маскируются).
- `buildQuestionnaireResponse(...)` принимает доменную модель `Template` (а не `TemplateResponse`).
- `create()`, `getQuestionnaire()`, `saveAnswers()` и `generate()` переведены на общий хелпер — единая политика «prefer snapshot», дублирование устранено.

## Тесты

`backend/src/test/java/com/docforge/document/DocumentServiceQuestionnaireTest.java` — 9 unit-тестов (JUnit 5 + Mockito STRICT_STUBS + AssertJ): snapshot-preference, live-fallback при `templateSnapshotId == null`, inverse skew (снапшот пуст, live не пуст → пустые pages), фолбэк только на `ResourceNotFoundException`, проброс прочих ошибок, `saveAnswers()`, `create()`, видимость (`visible=false` не фильтруется).

## Проверки

- `./gradlew test --tests "...DocumentServiceQuestionnaireTest"` — 9/9 green.
- `./gradlew test` — 171 тест, 5 предсуществующих падений (не связаны; подтверждено `git stash` на чистом дереве): `DocumentPermissionServiceTest > MANAGER`, `DocumentServiceImplIT create() snapshot`, `TemplateControllerIT PUT 409`, `TemplateServiceImplIT publish/update-published`. Новых падений нет.
- E2E через API: шаблон → PUT(questionnaire=q1) → publish → create doc → unpublish → PUT(questionnaire:null) → `GET /documents/{id}/questionnaire` вернул q1 из снапшота (до фикса — пусто).
- `/review` — approve-with-changes; все замечания закрыты (сужение catch, передача `e`, общий хелпер, стабилизация тестов).
