# BUG-061 — currentUserId() глушит исключение внутри транзакции

- **Статус:** закрыт (2026-10-24)
- **Коммиты:** `83aa862` (фикс), `317c038` (устаревший assert MANAGER/SHARE)
- **Агенты:** `/backend`, `/test`, `/review`

## Суть

```java
private UUID currentUserId() {
    String login = currentLogin();
    if (login == null) return null;
    try {
        return userService.getCurrentUser(login).id();
    } catch (Exception e) {
        return null;   // ← исключение поймано ВНУТРИ транзакции
    }
}
```

`UserServiceImpl.getCurrentUser(login)` — `@Transactional(readOnly = true)` с
propagation `REQUIRED`, то есть он **присоединяется** к транзакции вызывающего.
Когда пользователя нет в `users`, бросается `ResourceNotFoundException`;
транзакционный интерсептор помечает **общую** транзакцию как rollback-only.
Исключение глушится, метод выглядит успешным, но на коммите вылетает
`UnexpectedRollbackException: Transaction silently rolled back because it has
been marked as rollback-only`.

Воспроизводилось на тестах с `@WithMockUser("testuser")` — пользователя с таким
логином в `users` нет:
`TemplateServiceImplIT.publish()`, `TemplateServiceImplIT.update()`,
`TemplateControllerIT.update_publishedTemplate_returns409`,
`DocumentServiceImplIT.create_setsSnapshotReference`.

## Решение

- `UserService`: не бросающие лоупы
  `Optional<UserDTO> findUser(String login)` и `Optional<UserDTO> findUserById(UUID id)`
  — без исключительного пути, `null`-безопасные (`Optional.empty()`, репозиторий
  не трогается);
- `TemplateServiceImpl.currentUserId()`, `DocumentServiceImpl.currentUserId()`,
  `AuditServiceImpl` используют их; атрибуция остаётся best-effort (`null`),
  поведение для существующего пользователя не изменилось (`created_by`,
  `saved_by`, `authorName`, `audit_log.user_id`);
- `DocumentServiceImpl` и `AuditServiceImpl` больше **не импортируют**
  `user.UserRepository` — кросс-модульные импорты репозиториев устранены;
- `DocumentServiceImpl.toRevisionDTO` разрешает удалённого автора без
  исключения (уровень лога снижен до `debug`).

## Тесты

- `UserServiceImplTest` — 6 (не бросает, `Optional.empty()`, `null`-аргументы);
- `TemplateServiceUnknownUserIT` — 3 (`publish`, `saveVersion` под
  неизвестным логином: нет `UnexpectedRollbackException`, запись версии
  закоммичена, `created_by IS NULL`, аудит записан с `user_id IS NULL`);
- `DocumentServiceUnknownUserIT` — 2 (`saveRevision` под неизвестным логином;
  `listRevisions` для ревизии с **удалённым** автором — именно этот путь
  раньше отравлял транзакцию);
- все новые тесты проверены RED на старом коде (6/6 падали с
  `UnexpectedRollbackException`); guard «пользователя нет в `users»» сделан на
  чистом SQL, чтобы тесты компилировались и на старом дереве;
- **весь backend: 345 тестов, 0 падений** (было 5).

## Ревью

**APPROVE.** Замечания закрыты: документный IT теперь бьёт по модулю
`document` (ревизия с удалённым автором), guard переведён на SQL, убраны
тавтологичные утверждения в unit-тесте.
