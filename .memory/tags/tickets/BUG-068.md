# BUG-068 — Авторизация на изменение шаблона (write-scope)

- **Статус:** закрыт (2026-10-24)
- **Коммит:** `2d5487c`
- **Агенты:** `/backend`, `/frontend`, `/migrate`, `/test`, `/review`
- **Источник:** ревью BUG-058/BUG-059 (BLOCKER «обход через экспорт» и WARNING 2)

## Суть

В модуле шаблона не было проверки владения на **изменяющих** операциях: любой
аутентифицированный пользователь мог:

- `PUT /api/templates/{id}` — изменить чужой шаблон;
- `DELETE /api/templates/{id}` — удалить;
- `POST /api/templates/{id}/publish|unpublish` — публиковать чужой черновик;
- `POST /api/templates/{id}/versions` — создать черновик версии в чужом шаблоне;
- `POST /api/templates/{id}/rollback/{v}` — **откатить чужой шаблон** на любую
  версию: `rollback()` переносит содержимое снимка в живой шаблон, а
  `registry.published` остаётся `true` → опубликованный шаблон начинал отдавать
  всем черновой контент (воспроизведено: `GET /api/templates/{id}` после отката
  отдавал `DRAFT_SECRET_BODY`);
- `POST /api/templates/{id}/validate` и `.../scripts/test` — read-оракулы:
  метаданные черновика (коды параметров, id вопросов, метки блоков) и текст
  исключения Python-скрипта (содержит литералы скрипта).

## Решение

**Backend** (`TemplateServiceImpl.assertCanModify`):

- правило одно: **владелец** (`template_registry.owner_id`) или **администратор**
  (`ROLE_ADMIN` в authorities либо `users.is_admin`), иначе **403**
  «Нет прав на изменение шаблона»;
- fail closed: неизвестный логин (нет в `users`) или отсутствие аутентификации →
  отказ; `ROLE_ADMIN` проверяется **до** поиска пользователя;
- правило живёт в сервисе, вызывающий резолвится из `SecurityContextHolder` —
  обойти нельзя ни через другой эндпоинт, ни прямым вызовом сервиса;
- защищено 8 операций: `update`, `delete`, `publish`/`unpublish` (в общем
  `setPublished`), `saveVersion`, `rollback`, `validate`, `testScript`;
- `TemplateListItemResponse` получил `ownerId` (клиенту нужно знать владельца);
- **V019__backfill_template_owner.sql** — восстанавливает `owner_id` для
  легаси-строк из `template_version.created_by` (самая ранняя версия), затем из
  `audit_log` (`entity_type='TEMPLATE'`, `action='CREATE'`); строки без
  провенанса остаются admin-only. В dev-базе восстановлена 1 строка из 830 —
  легаси-данные без авторства.

**Frontend**: `getTemplateMutationRights(template, user)` (owner-or-admin,
fail-closed) → publish/unpublish/delete/«Сохранить версию»/«Откатить» скрыты
для чужих шаблонов (админу доступны); обработчики перепроверяют права; текст
403 от backend показывается через общий `api/errorMessages.ts`. Удалён
мёртвый дубль `TemplateList.tsx`. `Template.ownerId` → `string | null`.

## Тесты

- `TemplateWritePermissionIT` — 10: посторонний → 403 на **всех 8** операциях
  и «ничего не изменилось» (тело/флаг/версии/строка реестра), владелец →
  операции проходят (update опубликованного → 409), админ → может изменить
  чужой шаблон, неизвестный логин/нет аутентификации → 403, `ownerId` в списке.
- Починены **73** сломавшихся существующих теста: они использовали
  `@WithMockUser("testuser")` (нет в `users`) и теперь аутентифицируются как
  реальный владелец/админ (`TestAuth`).
- Новые хелперы: `TestAuth` (SecurityContext + `TestSecurityContextHolder`,
  восстановление в `finally`) и `AuditTestSupport` (детерминированное ожидание
  асинхронного аудита — иначе `@AfterEach` падал на FK `audit_log → users`).
- **Backend: 356 тестов, 0 падений**; фронт: 22 файла / 198 тестов.

## Ревью

**APPROVE** (без блокеров). Закрытые замечания: `ROLE_ADMIN` проверяется до
поиска пользователя (иначе ветка была недостижима), HTTP-путь теста дописан
инвариантами «ничего не изменилось», инвариант BUG-061 закреплён на
незащищённом пути (`documentService.create`), `AuditTestSupport` детерминирован.
Follow-up: **BUG-072** (JwtAuthFilter: неизвестный логин → 500 вместо 401/403).
