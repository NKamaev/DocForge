# BUG-067 — HttpMessageNotReadableException → 500 вместо 400

- **Статус:** закрыт (2026-10-25)
- **Коммит:** `5a96633`
- **Агенты:** `/backend`, `/test`, `/review`
- **Источник:** случайная находка при BUG-019 (невалидный enum в теле)

## Суть

`PUT /api/templates/{id}` с `parameters[].type = "boolean"` (lowercase enum)
падал с `HttpMessageNotReadableException: Cannot deserialize value of type
…ParameterType from String "boolean"` и catch-all `@ExceptionHandler(Exception.class)`
отвечал **500 Internal Server Error** вместо 400.

Дополнительно (найдено на ревью): `handleValidation` собирал карту ошибок
через `Collectors.toMap` **без merge-функции** — две нарушенных валидации на
одном поле (например, `name` = 501 пробел: `@NotBlank` + `@Size(max=500)`)
давали `IllegalStateException: Duplicate key` → тоже 500.

## Решение

- `GlobalExceptionHandler.handleMessageNotReadable(...)` → **400** `ProblemDetail`
  «Некорректное тело запроса: <причина>»; имена пакетов/классов в причине
  вычищаются регэкспом (`…`), чтобы не утекали внутренние имена Jackson/JVM;
  стектрейс пишется в лог (маскированный баг десериализатора должен быть виден);
- `handleValidation` — merge-функция `(first, second) -> first`.

## Тесты

`GlobalExceptionHandlerTest` — 7: неизвестное значение enum, битый JSON,
неверный тип поля (`{"name":{...}}`) и контейнера (`"parameters":"oops"`),
duplicate-constraint регрессия (501 пробел → 400, `errors` содержит одну
запись), валидный запрос → 200, битый query-параметр → 400 через прежний
`TypeMismatchException`-обработчик. Проверено, что все 4 новых кейса падают на
коде до фикса. **Backend: 493 теста, 0 падений.**

Замечание: `"name": 123` **не** является ошибкой — Jackson молча приводит
числовые скаляры к `String`; вместо этого в тестах использованы настоящие
несоответствия типов.

## Ревью

**APPROVE** (WARNING про duplicate-key закрыта и закреплена тестом).

## Не входит (заведено отдельно)

- **BUG-079** — catch-all в `GlobalExceptionHandler` затеняет стандартный
  `DefaultHandlerExceptionResolver`: 405/415/406/400/404/413 (`HttpRequestMethodNotSupported`,
  `HttpMediaTypeNotSupported`, `MissingServletRequestParameter`,
  `NoHandlerFound`, `MaxUploadSizeExceeded` и т.д.) всё ещё отвечают 500.
