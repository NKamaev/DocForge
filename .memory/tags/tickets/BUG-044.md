# BUG-044 — Счётчик шаблонов за неделю на главной не работает

- **Статус:** закрыт (2026-10-22)
- **Создан:** 2026-10-13
- **Источник:** audit_log 285, `/`

## Суть

На главной странице карточка «Шаблонов» показывала зелёный тег
«+2 за неделю» — значение было **жёстко закодировано** в `HomePage.tsx`,
реальное количество созданных за неделю шаблонов не запрашивалось.
На момент проверки в БД было 53 шаблона, созданных с понедельника.

## Решение (коммит `a3e4f2b`)

- **Backend:** `GET /api/templates` принимает необязательный
  `createdAfter` (ISO `OffsetDateTime`); `TemplateServiceImpl.list(...)`
  добавляет Specification `createdAt >= createdAfter`.
- **Frontend:** утилита `frontend/src/utils/startOfWeek.ts` — понедельник
  00:00 локального времени. `HomePage` запрашивает
  `getTemplates({ page:0, size:1, createdAfter: startOfWeek().toISOString() })`
  и рендерит `+{totalElements} за неделю` (при ошибке тег не показывается).
- **GlobalExceptionHandler:** `TypeMismatchException` → **400** с полем
  `parameter` (раньше кривой query-параметр давал 500 + stack trace).
- **Тесты:**
  - `startOfWeek.test.ts` — 4 кейса (четверг/воскресенье/понедельник,
    отсутствие мутации).
  - `HomePage.test.tsx` — 3 кейса (передаётся `createdAfter` = начало недели;
    рендерится `+7 за неделю`; ошибка → тега нет).
  - `TemplateListCreatedAfterIT` — 5 кейсов: фильтр, граница `>=` включительно
    (`boundary` / `boundary-1ms`), литеральный UTC `Z`, кривой параметр → 400.
  - Frontend suite **127/127**, targeted backend **18/18**.

## Проверка

API `totalElements=53` = `SELECT count(*) ... created_at >= date_trunc('week', now())`;
в браузере `+53 за неделю`, ошибок в консоли нет.

## Ревью

**APPROVE.** Замечания:
- исправлено #1 (malformed `createdAfter` → 400) и #2 (тест границы `>=`);
- follow-up (не блокирует): календарная неделя vs trailing 7 дней —
  оставлена календарная (соответствует формулировке «за текущую неделю»);
  `+0 за неделю` показывается как есть; два count-запроса на главной можно
  объединить в stats-эндпоинт; 5 позиционных параметров `list(...)` —
  кандидат на record-query.
