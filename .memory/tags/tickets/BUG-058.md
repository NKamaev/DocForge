# BUG-058 — Инстанцирование черновых версий опубликованного шаблона

- **Статус:** закрыт (2026-10-24)
- **Коммит:** `8a1516b`
- **Агенты:** `/backend`, `/frontend`, `/test`, `/migrate`, `/review`
- **Источник:** ревью BUG-052 (WARNING 1)

## Суть

`POST /api/documents` принимал `templateVersionNumber` без проверки, что версия
опубликована. Любой аутентифицированный пользователь мог закрепить документ за
**черновиком** версии чужого опубликованного шаблона (`saveVersion` →
`bumpType` `MAJOR`/`MINOR`) и прочитать его содержимое.

Дополнительно: без явной версии документ закреплялся за `findLatestSnapshot` —
то есть за **последним сохранённым черновиком**, а не за последней
опубликованной версией.

## Воспроизведение (API)

1. Владелец: `PUT /templates/{id}` с телом `DRAFT_SECRET_BODY` →
   `POST /templates/{id}/versions` (MINOR) → черновик `10001`.
2. Владелец: `PUT` с телом `PUBLISHED_BODY` → `POST /templates/{id}/publish`
   → опубликованная `10002`.
3. Не-владелец: `POST /documents {templateId, templateVersionNumber: 10001}`
   → **201**, документ закреплён за черновиком; `POST /documents/{id}/generate`
   → в теле документа `DRAFT_SECRET_BODY`.

## Решение

**Backend** (`DocumentServiceImpl.create` + `TemplateService`):

- явная версия: версия должна существовать (**404**), для не-владельца —
  быть опубликованной (**403** «Нет доступа к черновой версии шаблона»), её
  Mongo-снимок должен существовать (**404**); «безснимковый» документ больше
  не создаётся;
- без явной версии: владелец — последняя версия (включая свои черновики);
  гость — последняя **опубликованная**; если строки версий есть, но
  опубликованных нет → **403** «Нет опубликованной версии шаблона»; откат на
  live-шаблон остался только для легаси-шаблонов без строк версий;
- «опубликована» = `bumpType` `PUBLISH`, легаси `NULL` (до появления
  `bump_type`) или `ROLLBACK`, откатанный **с** опубликованной версии
  (рекурсия по `rollback_from`, глубина ограничена); `MAJOR`/`MINOR` — черновики,
  доступны только владельцу;
- снимок резолвится по `id` версии из PostgreSQL
  (`template_snapshots._id == template_version.id`) с откатом на поиск по номеру
  версии — так «пин» документа и `GET /versions/{n}` всегда видят один снимок;
- `V018__template_version_legacy_publish.sql` помечает легаси-строки с
  `bump_type IS NULL` как `PUBLISH` (идемпотентно).

**Frontend** (`CreateDocumentModal`): в списке только инстанцируемые версии
(`PUBLISH`/легаси `NULL`), preselect — самая свежая из них, текст ошибки
backend читается из `ProblemDetail.detail`, подсказка «нет опубликованных
версий» больше не обещает успех там, где backend отвечает 403.

## Ревью

Три итерации `@review`. Закрытые замечания:

- **BLOCKER** — NPE при `ownerId == null` → `ownerId != null && ownerId.equals(...)`;
- **BLOCKER** — «безснимковый» документ для гостя (лайф-шаблон мог содержать
  черновик после отката) → 404/403, откат на live только для легаси;
- **BLOCKER** — `ROLLBACK` считался опубликованным → теперь только по
  provenance источника отката;
- **WARNING** — расхождение резолва снимков (пин vs чтение) → единый
  `findSnapshotOf` (по id + фолбэк по номеру);
- **WARNING** — `findLatestSnapshot` без фолбэка → тот же резолв;
- **WARNING** — фронт читал `message` вместо `detail` → исправлено;
- **WARNING** — вводящая в заблуждение подсказка → исправлена.
