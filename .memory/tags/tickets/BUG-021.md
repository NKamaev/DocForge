# BUG-021 — NPE в applyAnswers: switch на null type узла

- **Статус:** закрыт (2026-10-23)
- **Источник:** ревью коммита `16f5208`

## Суть

`DocumentController.applyAnswers()` делал:

```java
String type = (String) node.get("type");
return switch (type) { ... };
```

Java `switch` на `null` бросает `NullPointerException`. Узел без поля `"type"`
может появиться в `current_body` после правок TipTap/Yjs, поэтому
`GET /api/documents/{id}/export/docx|pdf` падал с **500**.

Воспроизведено через API: `PUT /documents/{id}/body` с телом, содержащим
`{"content":[{"type":"text","text":"typeless"}]}` (без `type`), затем экспорт →
500 в обоих форматах.

## Решение (коммит `9619f81`)

```java
return switch (String.valueOf(node.get("type"))) { ... };
```

- Узел без `type` (и `"type": null`) попадает в `default` и пробрасывается
  **как есть** — это совпадает с контрактом экспортёров
  (`DocxExportServiceImpl`/`PdfExportServiceImpl` уже используют
  `String.valueOf(type)` и рендерят `default -> children`).
- Не удаляем и не «нормализуем» узел: удаление теряет контент, а подстановка
  `"type":"text"` — догадка, которая может испортить block-узел.
- Побочно: `"type": {"a":1}` больше не даёт `ClassCastException`, а уходит в
  `default`.
