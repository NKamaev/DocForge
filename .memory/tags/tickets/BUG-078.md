# BUG-078 — numberedClause в ячейках/списках; clauseRef в шаблон-экспорте

- **Статус:** закрыт (2026-10-25)
- **Коммит:** `6e9ccb1`
- **Агенты:** `/backend`, `/test`, `/review`
- **Источник:** ревью BUG-066 (WARNING — остаток того же класса бага)

## Суть

После BUG-066 (текст пункта на верхнем уровне) тот же класс бага остался в
двух других рендер-путях и одна несогласованность:

1. **Ячейки таблицы** — содержимое ячейки рендерилось inline-only
   (`renderInlineChildren`): `numberedClause` (и любой block-узел) в ячейке
   молча терял текст;
2. **Пункты списка** — `renderList` рендерил только `paragraph`-детей пункта,
   `renderListItem` (PDF) — inline-only: `numberedClause` в пункте списка
   терял текст;
3. **Шаблон-экспорт** (`ExportController`, сырое тело шаблона) рендерил
   `clauseRef` по `attrs.label`/«п. ?», хотя нумерация уже была доступна.

## Решение

- ячейки таблицы и пункты списка рендерят block-детей через `renderNode`
  (отступы списков сохраняются для всех абзацев пункта);
- **маркер списка ставится на первого ребёнка**: `item=[numberedClause]` →
  «• 1. LIST_CLAUSE_TEXT» одной строкой (без пустого маркерного абзаца после
  контента — этот артефакт нашло ревью первого круга и он был закрыт);
  DOCX и PDF консистентны;
- шаблон-экспорт резолвит `clauseRef` через общий
  `ClauseNumbering.Result.refText`/`labelForRef`:
  `attrs.refId` → легаси `clauseId` → `attrs.label` (только непустая строка) →
  «п. ?» — теперь шаблонный и документный экспорт рендерят ссылки одинаково;
- общий `TipTapNodeTypes.isInlineType/isBlockType` для обоих экспортёров
  (списки типов больше не расходятся).

## Тесты

- экспортные suites +5/+5: пункт в ячейке (текст + метка в DOCX и PDF), пункт в
  списке (порядок маркера: «• 1. …» без хвостового маркера; `[clause, paragraph]`
  — маркер на пункте, оба текста на месте), пункт из двух абзацев (отступ
  списка сохраняется), фолбэки `refText` (пустая/не-строковая метка → «п. ?»);
- `ClauseNumberingTest` +2 (unit для `labelForRef`/`refText`).
- **Backend: 531 тест, 0 падений.**

## Ревью

Первый круг — **REQUEST CHANGES**: размещение маркера списка было привязано к
первому *параграфу*, а не к первому ребёнку (пустой маркерный абзац после
контента). После фикса и тестов-закреплений ревьюер подтвердил approve.
