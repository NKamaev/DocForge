# BUG-059 — Чтение чужих черновиков шаблона

- **Статус:** закрыт (2026-10-24)
- **Коммит:** `9f5d54a`
- **Агенты:** `/backend`, `/frontend`, `/test`, `/review`
- **Источник:** ревью BUG-052 (WARNING 2)

## Суть

Read-endpoints модуля шаблонов не проверяли владение: любой
аутентифицированный пользователь получал содержимое чужого **неопубликованного**
шаблона и его черновых версий:

- `GET /api/templates/{id}` — живое тело (body, parameters, scripts, questionnaire);
- `GET /api/templates/{id}/versions` — черновики в списке;
- `GET /api/templates/{id}/versions/{n}` — снимок черновика;
- `POST /api/templates/{id}/export/docx|pdf` — экспорт шаблона (контроллер
  читал `TemplateRepository` напрямую, минуя сервис → нарушение слоёв);
- `GET /api/templates` — список включал чужие черновики;
- `GET /api/templates/{id}/versions/diff` — diff раскрывал снимки черновиков.

## Решение

**Backend** (правила — в сервисе, контроллер передаёт только вызывающего):

- новые методы `TemplateService`: `getReadable`, `listVisible`,
  `listVersionsVisible`, `getSnapshotVisible`, `getDiffVisible`;
  внутренние `getById`/`listVersions`/`getSnapshot`/`getDiff`/`list` не тронуты
  (их зовёт модуль `document`);
- опубликованный шаблон доступен всем; черновик — владельцу и администратору
  (`ROLE_ADMIN`); чужие черновики отфильтровываются **в SQL** (пагинация и
  `totalElements` корректны);
- «опубликованность» версии — **тот же** источник истины, что в BUG-058:
  `PUBLISH` / легаси `NULL` / `ROLLBACK` с опубликованным источником;
- **исключение для коллаборации**: черновую версию может прочитать участник
  документа, привязанного к этой версии — новый
  `DocumentService.hasAccessibleDocumentForTemplateVersion(templateId, version, userId)`
  (реализация: `DocumentRegistryRepository.findByTemplateIdAndTemplateVersionNumber`
  + `DocumentPermissionService.hasPermission(..., DocumentPermission.READ)`);
  без этого ломалась бы совместная работа над документом, созданным владельцем
  из своей черновиковой версии (`/fill` грузит снимок по номеру версии);
- `ExportController` больше не импортирует `TemplateRepository` — экспорт идёт
  через `templateService.getReadable(...)`;
- `rollback()` опубликованного шаблона к черновику запрещён (409,
  `BusinessException`) — иначе живой опубликованный шаблон отдавал бы всем
  черновое содержимое (`published=true` + draft body);
- легаси-снимок без записи в `template_version` считается опубликованным и при
  чтении, и при инстанцировании (единая семантика);
- `resolveUserId` ловит только `ResourceNotFoundException` (падение БД → 500,
  а не тихая деградация к «только опубликованные»).

**Frontend**:

- конструктор шаблона: отдельные состояния 403 («Нет доступа к шаблону») и 404,
  read-only режим для не-владельцев с подсказкой «Вы не владелец шаблона —
  редактирование недоступно», write-действия только владельцу/админу, кнопка
  «Откатить» только владельцу (fail-closed `canRollback`);
- `authStore.isUserResolved` — единый источник текущего пользователя (без
  лишнего `/users/me` и без мигания кнопок у владельца);
- общий хелпер ошибок `frontend/src/api/errorMessages.ts`
  (`extractServerMessage`: сначала `ProblemDetail.detail`, потом `message`).

  на версии A не даёт доступ к черновику B»; `ROLLBACK` опубликованной версии

- фронт: `errorMessages.test.ts` (12), `templateAccess.test.ts` (16),

  тестов;
- `template.* + document.* + export.*` — 332 теста, 5 известных
  пре-существующих падений.

## Ревью

Две итерации. Первая — **REQUEST CHANGES**: BLOCKER «обход через экспорт» и
5 WARNING (гард отката, две семантики «published», проглоченное исключение в
транзакции, 403 вместо 404 в diff, фронтовый `message` вместо `detail`).
Вторая — **APPROVE**.

## Не входит (заведено отдельно)

- **BUG-068** — write-scope шаблона без проверки владельца: `PUT`, `POST
  /versions`, `POST /rollback/{v}`, `publish`, `unpublish`, `DELETE`, а также
  read-оракулы `POST /validate` и `POST /scripts/test` (возвращают метаданные
  черновика и текст исключения со скрипта).
- **BUG-070** — дубль BUG-068 (заведён фронтенд-агентом).
- **BUG-069** — `ShareDialog` читает `response.data.message` вместо `detail`
  (общий хелпер уже создан, осталось перевести на него).
