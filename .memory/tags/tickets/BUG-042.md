# BUG-042 — useCollaboration.test.ts: buildWsUrl-тесты падали из-за dev-ветки

- **Статус:** закрыт (2026-10-22)
- **Создан:** 2026-10-13
- **Источник:** известные предсуществующие падения frontend-набора

## Суть

Два теста `buildWsUrl` («derives ws:// from http: location», «derives wss://
from https: location») возвращали `ws://localhost:8080` вместо значения из
`window.location`.

**Уточнённая причина** (в тикете была неточность): мок `window.location` через
`Object.defineProperty` работал — в vitest-jsdom свойство `configurable`.
Фактическая причина — dev-ветка
`if (import.meta.env.DEV) return 'ws://localhost:8080'`, добавленная 2026-10-10
(`f56583c`) уже **после** тестов (2026-05-08). В vitest `DEV === true`, поэтому
функция выходила раньше чтения `location`.

## Решение (коммит `6e48427`)

- `buildWsUrl(env: WsEnv = import.meta.env, location = globalThis.location)` —
  чистая функция; поведение без аргументов идентично прежнему (единственный
  place-of-use — `useCollaboration.ts:48`).
- Дефолт `globalThis.location` вместо `window.location`: дефолт-аргумент
  вычисляется до тела, и в non-browser контексте `window` давал бы
  `ReferenceError` даже при заданном `VITE_WS_URL`.
- Тесты инжектят env/location напрямую, без глобальных моков; 6 кейсов:
  env wins, http→ws, https→wss, DEV-ветка, env>DEV, дефолтный путь.
- **Тесты:** `useCollaboration.test.ts` 11/11; полный frontend suite 115/115;
  `tsc -b` OK. **Ревью: APPROVE.**
