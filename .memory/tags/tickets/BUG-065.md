# BUG-065 — NodeResolver читает clauseId вместо id/refId: clauseRef всегда «п. ?»

- **Статус:** закрыт (2026-10-25)
- **Коммит:** `6840dd9`
- **Агенты:** `/backend`, `/test`, `/review`
- **Источник:** ревью BUG-019 (WARNING 5)

## Суть

TipTap-схема пишет идентификатор пункта в `attrs.id`
(`NumberedClauseNode.tsx`), а ссылку — в `attrs.refId` (`ClauseRefNode.tsx`).
`NodeResolver` же читал `attrs.clauseId` **для обоих**:

- `buildClauseNumberingMap` на реальных документах всегда возвращал пустую карту;
- каждый `clauseRef` экспортировался как **«п. ?»**.

## Воспроизведение (API)

Тело с `numberedClause` (`attrs.id`) и `clauseRef` (`attrs.refId`) →
DOCX/PDF содержали «п. ?» вместо «п. 1»/«п. 2».

## Решение

`backend/src/main/java/com/docforge/export/NodeResolver.java`:

- `buildClauseNumberingMap` ключует по `attrs.id` (легаси-фолбэк —
  `attrs.clauseId`);
- `resolveClauseRef` читает `attrs.refId` (легаси-фолбэк — `attrs.clauseId`);
- новый хелпер `firstAttr(node, keys…)` — приоритет нового имени, пустое
  значение не затеняет легаси.

Проверено API: пункты `c1,c2,c3(hidden),c4` и ссылки на `c1,c2,c4` →
«п. 1», «п. 2», «п. 3» (скрытый по условию пункт **не** занимает номер —
нумерация строится по отфильтрованному дереву, BUG-019), «п. ?» отсутствует.

## Тесты

- `NodeResolverTest` — 26: реальные формы схемы (`id`/`refId`), вложенные
  пункты («2.1»), легаси `clauseId` и кросс-формы (легаси-ссылка на
  «новый» пункт и наоборот), неизвестный/пустой `refId` → «п. ?», приоритет
  `id`/`refId` над `clauseId`, обход (пункт вне clause-контейнера не
  нумеруется), `id` без значения → фолбэк на `clauseId`;
- `DocumentControllerApplyAnswersTest` — кейс скрытого пункта: ссылки
  пропускают его номер (`ref1=п. 1, ref2=п. 2, ref4=п. 3`).
- **Backend: 464 теста, 0 падений.**

## Ревью

**APPROVE.** WARNING (вынесена в критерий BUG-066): нумерация в экспорте
считается по вложенности и всегда decimal, тогда как редакторский
`AutoNumberingPlugin` учитывает `attrs.level`, `listStart` (сброс счётчиков) и
`numberingStyle` (decimal/alpha-ru/alpha-en) — при фиксе BUG-066 нужен паритет.
SUGGESTION (добавлено в BUG-076): `previewRenderer.buildStaticLabels` строит
метки по сырому дереву до фильтрации условий — скрытые пункты занимают номера
в подписях предпросмотра.

## Связанные

- BUG-066 (текст видимого numberedClause теряется + паритет нумерации),
  BUG-019 (фильтрация условий), BUG-076 (метки предпросмотра).
