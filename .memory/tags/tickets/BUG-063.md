# BUG-063 — current_body без структурной валидации: CCE/500 при экспорте

- **Статус:** закрыт (2026-10-25)
- **Коммит:** `75748cd`
- **Агенты:** `/backend`, `/test`, `/review`
- **Источник:** ревью BUG-021 (WARNING 1)

## Суть

`PUT /api/documents/{id}/body` принимал произвольный JSON
(`UpdateBodyRequest(@NotNull Object currentBody)`), поэтому в `current_body`
могли попадать массивы, строки и узлы с не-объектными `attrs`. При экспорте это
превращалось в `ClassCastException`/`NPE` → **500**:

- `Map<String, Object> bodyMap = (Map<String, Object>) body` — тело-массив/строка;
- `Map<String, Object> attrs = (Map<String, Object>) node.get("attrs")` —
  `{"type":"parameterField","attrs":"junk"}`;
- `(String) attrs.get("parameterCode")` — `parameterCode: 42`;
- `String type = (String) node.get("type")` в экспортёрах — `type: 42`;
- `switch (markType)` с `null`-типом метки (`marks: [{}]`) → NPE;
- `(String) attrs.get("borderTop")` в PDF — `borderTop: 123`;
- `Object::toString` на `null`-элементе `displayNames`.

## Решение

**Граница записи** — новый `com.docforge.document.TipTapBodyValidator`:

- корень — объект; узлы — объекты; `type`/`text` — строки; `attrs` — объект;
  `marks`/`content` — массивы; **элементы `marks` — объекты** с опциональным
  строковым `type`; глубина ≤ 500;
- нарушение → `ValidationException` → **422** с точным JSON-путём
  (`currentBody.content[0].marks[0]`);
- `DocumentServiceImpl.updateBody` и `restoreRevision` валидируют до записи
  (легаси-ревизия с мусором больше не может отравить `current_body`).

**Чтение/экспорт (defence in depth):**

- `DocumentController.requireBodyMap(body)` → 422 вместо CCE; `applyAnswers`
  использует `instanceof` для `attrs`/`parameterCode`;
- экспортёры (DOCX/PDF) переведены на хелперы `asMap(...)`/`str(...)`:
  не-строковые значения атрибутов больше не бросают; `switch` по типу метки
  null-безопасен; `displayNames` с `null`-элементами не даёт NPE;
- `NodeResolver` — `instanceof`-гварды на `content`.

## Тесты

- `TipTapBodyValidatorTest` — 18 (формы узлов, marks-элементы, пути ошибок,
  граница глубины 500/501);
- `DocumentBodyValidationIT` — 26: граница записи (422 + «ничего не
  сохранено», мусор после валидного тела не затирает его), экспорт легаси-мусора
  (посеян мимо валидатора через `DocumentRepository`) → 200 в оба формата,
  восстановление невалидной ревизии → 422, регрессия подстановки параметров.
- **Backend: 422 теста, 0 падений.**

## Ревью

Две итерации. Первая — REQUEST CHANGES (WARNING: граница записи пропускала
тела, которые всё ещё роняли экспорт — `marks: ["bold"]`, `displayName: 42`).
После доработки — ревью нашло ещё два BLOCKER-а, которые я внес «по пути»
(снятие лишнего `String.valueOf` в `switch` по типу метки вернуло NPE; слепой
каст `border*` в PDF), оба закрыты и закреплены тестами. Итог — APPROVE.

## Не входит (заведено отдельно)

- **BUG-074** — невалидные тела всё ещё попадают в экспортёры другими путями:
  `generate()` (без валидации), тела шаблонов (`PUT /templates/{id}` →
  `ExportController`), Yjs-персистентность; плюс глубокая терпимость
  экспортёров (`content: ["junk"]`, `marks: ["bold"]` в легаси-строках).
