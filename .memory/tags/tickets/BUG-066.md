# BUG-066 — Экспорт теряет текст видимого numberedClause

- **Статус:** закрыт (2026-10-25)
- **Коммит:** `a063827`
- **Агенты:** `/backend`, `/test`, `/review`
- **Источник:** проверка BUG-019 (соседний дефект) + критерий паритета из ревью BUG-065

## Суть

`numberedClause` имеет `content: block+` (параграфы), но оба экспортёра
рендерили его детей **inline**:

- `DocxExportServiceImpl.renderNumberedClause` → `children.forEach(c -> renderInline(para, c, ctx))`;
- `PdfExportServiceImpl` `case "numberedClause"` → `children.forEach(c -> renderInline(sb, c))`.

`renderInline` не обрабатывает `paragraph`, поэтому **текст каждого видимого
нумерованного пункта полностью терялся** в DOCX и PDF. Метка пункта тоже не
печаталась.

Дополнительно (критерий из ревью BUG-065): печатная метка должна совпадать с
редакторским `AutoNumberingPlugin` — до фикса бэкенд считал по вложенности и
всегда decimal, тогда как редактор учитывает `attrs.level`, `listStart` и
`numberingStyle` (decimal/alpha-ru/alpha-en).

## Воспроизведение (API)

Тело с `numberedClause` (`CLAUSE_TEXT`) → DOCX/PDF не содержали `CLAUSE_TEXT`
вообще; ссылки `clauseRef` давали «п. ?» (см. BUG-065).

## Решение

**Новый `com.docforge.export.ClauseNumbering`** — точный порт
`buildLabels` из `frontend/src/components/template-designer/extensions/NumberedClauseNode.tsx`:

- обход **всех** узлов в порядке документа (семантика `doc.descendants`);
- `level = clamp(attrs.level, 1..5)` (по умолчанию 1);
- `attrs.listStart` → сброс **всех** счётчиков; счётчики выше уровня обнуляются;
- счётчик уровня инкрементируется, стиль уровня запоминается;
- метка = сегменты уровней 1..level, отформатированные своими стилями,
  соединённые `.` + точка в конце («1.», «2.1.», «а.», «1.а.»);
- `byId` — по `attrs.id` (легаси `clauseId`), `byNode` — `IdentityHashMap`
  (порядковые метки не должны схлопываться для равных узлов);
- скрытые по условию пункты исключаются, потому что метки строятся по
  **отфильтрованному** дереву (BUG-019).

**Экспортёры:** содержимое пункта рендерится через `renderNode` (block-путь),
метка печатается жирным префиксом первого абзаца (отдельный абзац, если первый
ребёнок — не параграф). `RenderContext` (DOCX) и передача numbering через
`renderNode` (PDF) — без состояния в синглтонах.

**`NodeResolver.resolveClauseRef`** → «п. <метка>» в формате редактора
(«п. 1.», «п. 2.1.») — паритет с `ClauseRefNode` (`п. {label}`); неизвестная
ссылка — «п. ?».

## Тесты

- `ClauseNumberingTest` — 4 (identity-keying, легаси, смешанные стили);
- `NodeResolverTest` — 34: паритет с плагином — `listStart` перезапускает
  нумерацию (включая экзотику «0.1.» на вложенном уровне), `level` clamp
  (9 → «0.0.0.0.1.»), `alpha-ru`/`alpha-en`, неизвестный стиль → decimal,
  легаси `clauseId`;
- `DocxExportServiceImplTest`/`PdfExportServiceImplTest` — +9/+9: текст и метка
  пункта присутствуют, нумерация продолжается, `alpha-ru` даёт «а./б.»;
- `DocumentControllerApplyAnswersTest` — ссылки в формате «п. 1.», скрытый
  пункт не занимает номер.
- **Backend: 486 тестов, 0 падений.**

## Ревью

**APPROVE.** Найденное вынесено в **BUG-078**: пункт внутри ячейки таблицы или
пункта списка всё ещё теряет текст (там inline-only обход), и шаблон-экспорт
не резолвит `clauseRef` по нумерации. Попутное: **BUG-077** — кириллица в PDF
рендерится как `#` (резолвер берёт base-14 Times-Roman вместо NotoSerif).

## Связанные

- BUG-065 (метки и ссылки), BUG-019 (фильтрация условий до нумерации),
  BUG-077 (шрифты PDF), BUG-078 (остаточные рендер-пути).
