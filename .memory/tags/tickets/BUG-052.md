# BUG-052 — POST /api/documents без проверки доступа к шаблону и папке-цели

- **Статус:** закрыт (2026-10-22)
- **Источник:** ревью BUG-050

## Суть

`POST /api/documents` принимал любой `templateId` и любой `folderId`:
- можно было инстанцировать **чужой неопубликованный** шаблон (черновик);
- можно было создать документ в **чужой папке**.

Воспроизведено на dev: пользователь A → документ из draft-шаблона B = 201;
A → документ в папке B = 201.

## Решение (коммит `07bef1d`)

Проверки перенесены в `DocumentServiceImpl.create` (единая точка, без двойной
загрузки шаблона; внутренние вызовы сервиса не могут обойти):

```java
TemplateResponse template = templateService.getById(templateId);
if (!template.published() && !ownerId.equals(template.ownerId()))
    throw new AccessDeniedException("Нет доступа к шаблону");
if (folderId != null
        && !folderPermissionService.hasPermission(folderId, ownerId, FolderPermission.WRITE))
    throw new AccessDeniedException("Нет прав на папку-цель");
```

- `GET /api/templates/{id}` возвращает `published` + `ownerId`.
- **Тесты:** `DocumentCreatePermissionIT` — 9 кейсов:
  - чужой draft → 403 (нет строки в PG и документа в Mongo);
  - свой draft → 201;
  - чужой опубликованный → 201;
  - чужая папка: не-участник → 403, `VIEWER` → 403, `EDITOR` → 201;
  - своя папка → 201;
  - несуществующие template/folder → 404.
- Проверено в dev: оба вектора → 403, happy-path 201/404.
