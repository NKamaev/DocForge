# BUG-053 — Дубли снимков шаблона (template_snapshots) → 500 при создании документа

- **Статус:** закрыт (2026-10-22)
- **Создан:** 2026-10-22
- **Источник:** обнаружено при воспроизведении BUG-039

## Суть

`POST /api/documents` с `templateVersionNumber` возвращал **500**:

```
IncorrectResultSizeDataAccessException:
Query { "template_id": <uuid>, "version_number": 1 } returned non unique result
  at TemplateServiceImpl.getSnapshot(...)
  at DocumentServiceImpl.create(...)
```

UI всегда передаёт `templateVersionNumber` (выбранная версия из
`GET /api/templates/{id}/versions`), поэтому создание документа из интерфейса
ломадось. CLI-создание без версии проходило (201), т.к. шло через
`findLatestSnapshot → findById`.

## Причина

1. `TemplateServiceImpl.setPublished` вычислял следующую версию **только по
   PostgreSQL**: `versionRepository.findMaxVersionNumber(id) + 1`.
2. Снимок пишется в MongoDB отдельно от PG-строки `TemplateVersion`, без
   атомарности. Осиротевший снимок (PG-строка откатилась/не создалась) не
   учитывался → следующая публикация брала тот же номер → дубль
   `(template_id, version_number)`.
3. `TemplateSnapshotRepository.findByTemplateIdAndVersionNumber` возвращал
   `Optional` → при дублях Spring бросал `IncorrectResultSizeDataAccessException`.

Подтверждено профайлером Mongo: `nreturned=2`, `docsExamined=53`.

## Решение (коммит `d80c55a`)

- `TemplateSnapshotRepository`:
  - `findFirstByTemplateIdAndVersionNumberOrderByCreatedAtDesc(UUID, int)`
  - `findFirstByTemplateIdOrderByVersionNumberDesc(UUID)`
  - старый `findByTemplateIdAndVersionNumber` удалён.
- `getSnapshot` использует ordered finder → при исторических дублях
  детерминированно возвращает самый новый снимок, без исключения.
- `setPublished`: `nextVersion = max(pgMax, mongoMax) + 1`, где `mongoMax` —
  максимальная версия существующих снимков шаблона. Осиротевший снимок больше
  не приводит к коллизии.
- **Тесты:** 3 unit-регрессии (ordered finder, orphan-collision v5→v6,
  pgMax fallback) + **IT с двумя реальными дублями** в Mongo (проверяет
  `count == 2`, отсутствие исключения и выбор newest).
  `./gradlew test --tests 'com.docforge.template.*'` → 23 теста, 20 pass;
  3 падения — известные пре-существующие `UnexpectedRollbackException`.
- **Dev-данные:** дубли в `template_snapshots` очищены (оставлен самый новый),
  0 групп дублей.
- **Проверка в UI:** создание → 201 → переход на `/documents/{id}/fill`.

## Ревью

REQUEST CHANGES → исправлено:
- **W4** (тест-заглушка не ловит реальные дубли) — добавлен интеграционный тест.
Вынесено в отдельные тикеты:
- **BUG-054** (BLOCKER B1, предсуществующий) — `publish()` и `saveVersion()`
  используют один `version_number`: publish инкрементит `max+1`, saveVersion —
  `major*10000+minor` → возможен `DataIntegrityViolationException` (500).
- **BUG-055** (W2/W3) — нет unique-индекса `(template_id, version_number)`,
  нет пессимистичной блокировки в publish (гонка), publish не идемпотентен.
