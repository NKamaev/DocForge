## Постановка задачи (от пользователя)

```
В редакции/ревизии не сохраняется история изменений в текст документа.
Только история изменений опросного листа.
```

---

## Интерпретация

Пользователь редактирует тело документа (TipTap-редактор) — ревизия не создаётся.
Ревизия создаётся только когда пользователь меняет ответы в опросном листе.

Ожидаемое поведение: ревизия должна создаваться (или обновляться) при любом изменении документа — как при изменении ответов, так и при редактировании текста тела.

---

## Причина ошибки

**Корень проблемы:**  
Автосохранение ревизии вызывается только из `QuestionnairePage.tsx` при изменении ответов (debounce 500 мс), и не вызывается при изменении тела документа в `DocumentWorkspace`.

**Цепочка сбоя:**  
1. Пользователь редактирует текст в TipTap → `onUpdate` в `DocumentWorkspace` → сохраняется `currentBody` через `documentsApi.saveBody()`.
2. `saveBody` обновляет тело документа, но ревизию **не создаёт**.
3. `documentsApi.saveRevision()` вызывается только в `QuestionnairePage.tsx` при `onAnswersChange` (дебаунс 500 мс).
4. Если пользователь редактировал только текст — в истории редакций изменений нет.

## Поэтапное исполнение

1. **Изучить** `DocumentWorkspace.tsx` — найти `onUpdate` callback, который сохраняет тело.
2. **Добавить debounce** (500–1000 мс) на изменение тела документа аналогично тому, как это сделано для ответов.
3. **Вызывать `saveRevision`** при изменении body, передавая комментарий `'Автосохранение'`.
4. **Убедиться в отсутствии двойного сохранения**: если оба изменения (body + answers) происходят одновременно — ревизия должна создаваться один раз (или допустимо создать две подряд — уточнить у заказчика).
5. **Проверить** что `saveRevision` на бэкенде сохраняет актуальный `currentBody` (а не предыдущий) — судя по коду `DocumentServiceImpl.saveRevision()` он читает `doc.getCurrentBody()` из БД, поэтому порядок `saveBody` → `saveRevision` важен.
