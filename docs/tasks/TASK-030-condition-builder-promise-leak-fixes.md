## Постановка задачи

По результатам ревью коммита `5588f0c` (раскрытие полей справочника в ConditionBuilder) выявлены четыре WARNING:

1. **Утечка промиса** — `Promise.all` продолжает выполняться после закрытия модала и вызывает `setDirFields` на уже закрытом компоненте.
2. **Stale state** — при повторном открытии модала `dirFields` не сбрасывается, могут остаться данные от предыдущего вызова с другим набором параметров.
3. **Silent catch** — `catch(() => {})` молча проглатывает ошибки сети; пользователь видит DIRECTORY-параметр без подполей и не понимает причину.
4. **Несоответствие дефолтного параметра** — при инициализации `rows` берётся `parameters[0]?.code`, а при `addRow` — `expandedParams[0]?.code`; поведение непоследовательное.

---

## Интерпретация

Все четыре проблемы находятся в одном файле и логически связаны с механизмом загрузки справочников в `ConditionBuilder`. Фиксы небольшие, декомпозиция не нужна.

---

## Причина ошибки

**Корень проблемы:**
В `useEffect` запускается `Promise.all`, результат которого применяется безусловно — без проверки актуальности (жив ли компонент, не изменились ли параметры).

**Цепочка сбоя:**
1. Пользователь открывает модал → стартует `Promise.all` для загрузки справочников.
2. Пользователь быстро закрывает модал (или сразу открывает другой шаблон).
3. Промис завершается → `setDirFields` вызывается на закрытом/переключённом компоненте.
4. При следующем открытии `dirFields` содержит данные от предыдущей сессии.

## Поэтапное исполнение

1. **AbortController** — в `useEffect` создать `const controller = new AbortController()`, в cleanup возвращать `() => controller.abort()`. В `.then` проверять `if (controller.signal.aborted) return`.
2. **Сброс stale state** — в начале `useEffect` (после `if (!open) return`) добавить `setDirFields(new Map())`.
3. **Обработка ошибки** — заменить `catch(() => {})` на `catch((e) => console.warn('Failed to load directory fields', e))`. Опционально: добавить `dirFieldsError` state и показывать предупреждение в UI.
4. **Унификация дефолта** — при инициализации `rows` использовать первый код из `expandedParams` (вычислить его до `setRows`) или оставить пустым и инициализировать в `SimpleBuilder`.
