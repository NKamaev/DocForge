# Skill: memory-manager

## What I do

Управляю долговременной памятью проекта — файлами в `.memory/`. Память организована по
**тегам** (`.memory/tags/{category}/{file}.md`) и **датам** (`.memory/daily/`, `weekly/`, `monthly/`).
Все изменения версионируются в Git.

Единственный реестр тегов — `.memory/tag-index.md`. Не дублируй список тегов в других файлах.

## When to use me

- В начале новой сессии — загрузить релевантный контекст (архитектура, практики, специфика тикетов).
- При завершении значимой задачи или сессии — записать выводы.
- При повторяющейся проблеме или найденном решении — зафиксировать паттерн.
- По запросу пользователя — анализ истории или ретроспектива.

## Runtime compatibility

| Runtime | Как использовать |
|---------|------------------|
| opencode | `Skill("memory-manager")` |
| Kimi Code CLI и прочие без project-skills | Работать по блоку памяти в `AGENTS.md` — процедура та же, автозагрузка тегов выполняется в начале сессии |

Если рантайм не поддерживает skills, инструкции этого файла всё равно применимы вручную.

## Bootstrap (первый запуск в проекте без `.memory/`)

1. Создай каталоги: `.memory/{tags,daily,weekly,monthly}`.
2. Создай `.memory/tag-index.md` по шаблону `templates/tag-index.md`.
3. Скопируй нужные шаблоны из `templates/` в новый тег/тикет/день.
4. Добавь в `AGENTS.md` проекта блок автозагрузки памяти (см. `templates/AGENTS-memory-block.md`).
5. Зафиксируй: `git add .memory/ AGENTS.md && git commit -m "memory: bootstrap"`.

## Workflow

### 1. Загрузка контекста (перед решением задачи)

1. Прочитай `.memory/tag-index.md`. Индекс может быть большим — читай только секции, релевантные
   запросу, а не весь файл целиком (используй `Grep`/выборочное чтение).
2. Проанализируй запрос и определи релевантные категории/теги.
3. **Всегда загружай:** `best-practices.md` и набор `pitfalls-*.md` из любых категорий
   (путь вида `{category}/pitfalls-*.md` — см. индекс).
4. Догрузи остальные релевантные теги из `.memory/tags/{category}/`.
5. Если по ходу выяснилась нужда в дополнительном контексте — динамически подгружай теги.

### 2. Решение задачи

Работай, используя загруженный контекст.

**Приоритет «память vs код»:** актуальный код и данные приложения — источник истины.
Если тег противоречит коду — верь коду, а тег пометь устаревшим и обнови. Никогда не следуй
устаревшему тегу вопреки наблюдаемому поведению (см. вытекающие отсюда pitfall-теги).

### 3. Обновление памяти (после решения)

1. **Тикет:** создай/обнови `.memory/tags/tickets/TC-XXX.md` (или описательное имя, если тикета нет) —
   суть, решение, ссылки на код, TODO. Обнови статус.
2. Добавь тег в `.memory/tag-index.md` (секция `Tickets`), если он новый.
3. Проверь: появились ли новые архитектурные решения или важные выводы?
4. Если да — создай/обнови файл в `.memory/tags/{category}/` и зарегистрируй тег в `tag-index.md`.
5. Запиши краткий вывод сессии в `.memory/daily/YYYY-MM-DD.md` по шаблону `templates/daily.md`.

### 4. Агрегация

- **Еженедельно:** собери `.memory/daily/` за неделю → `.memory/weekly/YYYY-Www.md` (`templates/weekly.md`).
- **Ежемесячно:** собери недельные отчёты → `.memory/monthly/YYYY-MM.md`.
- **Политика «догона»:** если агрегация не делалась N недель/месяцев — сначала выполни пропущенные
  сводки, затем текущую. После агрегации переноси избыточные детали из daily в архив/удаляй.

### 5. Проверка целостности

Периодически (и перед коммитом крупной порции изменений) запускай валидатор:

```bash
scripts/memory-lint.sh        # index <-> файлы, битые ссылки, пустые теги
```

Он проверяет, что каждый файл под `.memory/tags/` есть в `tag-index.md` и наоборот, и что
внутренние ссылки в памяти не ведут в никуда.

### 6. Версионирование

**Исключение из общего правила «не коммитить без запроса»:** изменения в `.memory/` можно и нужно
коммитить как часть сессии (это версионируемая память проекта):

```bash
git add .memory/
git commit -m "memory: <описание изменений>"
```

Если проект запрещает авто-коммиты — сохрани изменения и предложи пользователю закоммитить.

### 7. Доработка скилла (приоритетная задача)

Если текущая структура тегов, шаблоны или инструкции неэффективны — предложи пользователю
доработать этот `SKILL.md` или `tag-index.md`. Скилл развивается по результатам использования.

## Правила именования и формата

- **Теги:** строчные латинские, цифры, дефисы (`architecture`, `best-practices`).
- **Тикеты:** `tickets/TC-XXX.md`, если тикет нумерованный; иначе описательное имя
  (`tickets/short-topic.md`). Один файл — один тикет/тема.
- **Файлы тегов:** `.memory/tags/{category}/{topic}.md` — категория = папка, один файл на тему.
- **Даты:** `YYYY-MM-DD` (день), `YYYY-Www` (неделя, ISO-8601), `YYYY-MM` (месяц).
- **Записи в теге:** обратная хронология (новые сверху), `## [YYYY-MM-DD HH:MM] Описание`.
- **Записи в daily:** `## [HH:MM] Краткое описание сессии`.
- **Свежесть:** в шапке тега указывай `Обновлено: YYYY-MM-DD` и, где применимо, **источник**
  (файл:строка, тикет, лог) — чтобы можно было отличить актуальное от устаревшего.

## Шаблоны

Готовые скелеты — в `templates/`:

| Файл | Назначение |
|------|-----------|
| `templates/tag-index.md` | заготовка реестра тегов |
| `templates/tag.md` | файл тега |
| `templates/ticket.md` | файл тикета |
| `templates/daily.md` | дневной лог |
| `templates/weekly.md` | недельная сводка |
| `templates/AGENTS-memory-block.md` | блок памяти для `AGENTS.md` проекта |

## Completion criteria

- [ ] Релевантные теги (`best-practices` + `pitfalls-*` + тематические) загружены до начала работы.
- [ ] Выводы сессии записаны в `.memory/daily/YYYY-MM-DD.md`.
- [ ] Новые знания добавлены в теги, теги зарегистрированы в `tag-index.md`.
- [ ] `scripts/memory-lint.sh` проходит без ошибок (index и файлы согласованы).
- [ ] Изменения в `.memory/` закоммичены либо сохранены с предложением коммита.
- [ ] Проведена агрегация / файлы памяти не превышают разумных лимитов (daily > 500 строк → сводка).
