# Bug Report → TaskTracker sync (via @task agent)

Синхронизирует сообщения об ошибках из `audit_log` (PostgreSQL) в TaskTracker MCP
через агента **`@task`**, который интерпретирует каждый отчёт и создаёт полноценную
задачу с постановкой, интерпретацией, файлами, этапами и чеклистом.

**CRITICAL: Не создавать задачи напрямую. Только через @task.**

## Процесс

### 1. Запросить непрочитанные сообщения

```sql
SELECT id, created_at, user_id, details::jsonb
FROM audit_log
WHERE entity_type = 'FEEDBACK'
  AND action = 'BUG_REPORT'
  AND (details::jsonb ->> 'task_id') IS NULL
ORDER BY created_at DESC;
```

Детали содержат JSON: `{"elements": [{"selector": "...", "label": "..."}], "url": "...", "description": "..."}`

### 2. Семантический анализ и дедупликация

Перед созданием задач выполнить анализ всех полученных записей:

- **Сгруппировать по URL** — записи с одинаковым URL скорее всего про один экран.
- **Сравнить описания** — если описания про одну и ту же проблему (layout, кнопка, логика), объединить в одну задачу.
- **Признаки дубликата:**
  - Совпадает URL (особенно если страница специфичная, а не общая)
  - Описания ссылаются на одну и ту же часть интерфейса
  - Одна проблема описывается с разных ракурсов («кнопки скрыты» + «элементы не влезают»)
- **Группировать до создания задач**, а не пост-фактум.

### 3. Для каждой группы передать в @task

Не создавать задачу напрямую. Вызвать `@task` с полными данными всех отчётов группы. В описании задачи указать все объединённые audit_log id.

### 4. @task выполнит

- **Интерпретацию**: определит модуль, слой, серьёзность, предполагаемую корневую причину
- **Создание задачи**: полный формат с Постановка / Интерпретация / Файлы для изучения / Файлы для изменения / Поэтапное исполнение / Чеклист тестирования
- **GitHub Issue**: создаст и свяжет с задачей
- **Отметку в audit_log**: проставит task_id

## Скрипт для автоматического запуска (deprecated)

См. `backend/bin/sync-feedback-to-tasks.sh` — не использовать напрямую.
Скрипт создаёт задачи без интерпретации, что приводит к низкокачественным таскам.
Используйте `@task` или `@feedback-sync` вместо скрипта.
